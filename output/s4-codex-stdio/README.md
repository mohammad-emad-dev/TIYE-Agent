# Native Windows synthetic subprocess stdio

Recorded 16 October 2026. **Eight peer scenarios and eight capture tests passed.**
S4/S6 remain partial; Phase 1 construction remains HOLD.

This cohort adds real Windows pipes and direct-child exit observation around the
[frozen framing policy](../s4-codex-framing/README.md). It launches a fixed Python
peer with an absolute path, an allowlisted scenario and Python isolated mode
(`-I`). No agent CLI, WSL, authentication, provider request, external command or
descendant is launched by the peer. Host model reviews are separate activities
recorded in [review.json](review.json).

## Observations

| Scenario | Required observation |
| --- | --- |
| `roundtrip` | Public Arabic/Japanese/emoji startup text echoed; one approval callback; one exact denial observed by peer; completion record and exit 0 |
| `eof-pending` | Approval followed by stdout EOF and exit 0; no write; late local reply refused |
| `truncated` | Valid completion JSON without LF; EOF classified as truncation despite exit 0 |
| `badexit` | Full completion record followed by exit 23; harness outcome remains `needs-attention` |
| `broken-stdin` | Peer closes stdin before its barrier; one 65,536-byte fault write observes a pipe error; no retry |
| `stdout-flood` | Retained prefix capped at 8,192 bytes; observed bytes exceed cap; harness aborts |
| `stderr-flood` | Concurrent stderr reader detects overflow; retained prefix capped at 4,096 bytes |
| `hang` | Pending approval receives no reply; 1.5-second activity deadline triggers direct-child termination |

Each scenario records the child return code, closed local connection, settled I/O
tasks, successful direct-child wait and no cleanup errors. stdout reads request
at most seven bytes, forcing fragmented delivery into the byte framer; this does
not preserve or measure OS write boundaries. stderr reads request at most 4,096
bytes and run concurrently with stdout and the exit wait.

The `roundtrip` case sends two bounded public writes: startup input and a planned
denial of the synthetic callback. A local `drain()` completion is not evidence
that the peer accepted a write. The peer's exact `fixture/replyObserved` message
supplies that additional observation for the denial. No approval acceptance,
real command execution or authorization flow is qualified. The broken-input
fault intentionally writes non-JSON bytes to a closed input pipe; its result is
`uncertain-write`, not a claim of zero bytes delivered.

Every case retains `taskSuccess: null`. `protocolStatus`, child return code and
the harness `outcome` are separate fields. EOF callbacks are labeled
`source: stdout-eof`; a wrapper closure requested during abort is labeled
`source: local-abort`, rather than treated as an observed EOF.

## Bounds and cleanup limits

The activity deadline starts **after subprocess creation**. Spawn duration is not
bounded by it. Direct-child wait has a separate two-second cleanup timeout and
stdin closure a one-second timeout. On a fault, the harness closes the local
reply path, requests termination if that direct child is still live, waits for
exit and settles or cancels I/O tasks. A timed-out stdin close aborts its
transport and records a cleanup error; that would fail the capture gate.

Raw stream files are retained prefixes. `observedBytes` counts only completed
reads, including the read that crossed a budget. It is not the total output
generated by the child or a complete post-kill drain. Captured prefix limits are
not a measurement or bound on all Python/OS transport memory. The hanging and
broken-input peers have a ten-second fallback sleep; neither normal expiration
is relied on for cleanup in the accepted capture.

Only the owned direct child is tested. No process-tree containment, PID reuse
defense, Job Object, shell behavior, WSL translation, concurrency, real CLI
backpressure or crash recovery is qualified. Private wrapper state is a local
convention, not a sandbox.

## Evidence and verification

Sources: [harness.py](../../feasibility/s6-wsl/codex-stdio/harness.py),
[peer.py](../../feasibility/s6-wsl/codex-stdio/peer.py),
[test_capture.py](../../feasibility/s6-wsl/codex-stdio/test_capture.py),
[run.py](../../feasibility/s6-wsl/codex-stdio/run.py).
The [evidence index](evidence.json) hashes frozen dependencies, captured schemas,
each scenario's JSON report and raw streams, and the original unittest streams.
Scenario file names use the table's mode plus `.json`, `.stdout.bin` and
`.stderr.bin`. For example: [roundtrip report](roundtrip.json),
[roundtrip stdout](roundtrip.stdout.bin), [broken-input report](broken-stdin.json).

From the repository root with the recorded Python runtime and RTK installed:

```powershell
rtk proxy python -B -X utf8 feasibility/s6-wsl/codex-stdio/run.py --check
rtk proxy python -B -X utf8 feasibility/s6-wsl/codex-framing/run.py --check
rtk proxy python -B -X utf8 feasibility/s6-wsl/codex-replay/run.py --check
```

The stdio `--check` verifies hashes and runs eight behavior assertions against
saved captures in the current process. It launches no new subprocess and makes
no timing requalification. The recorder without `--check` creates its output
directory exclusively and refuses an existing directory. Exploratory and
preflight launches preceded the final sealed capture; their results were not
substituted for its raw streams. Earlier measured sources and evidence remain
unchanged.
