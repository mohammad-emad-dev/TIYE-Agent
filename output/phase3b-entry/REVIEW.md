# Proposal review

Luna max completed its focused review. The parent adopted explicit cancellation
boundaries and separate lifecycle closure evidence: request/read identities and
budgets are reserved before invocation, successful reads are retained without
repeating or continuing after stop, and an end frame never proves local closure.
Required tests now include extra bytes/disconnect/close error/abort after a tool
candidate and stop before/after the read and request dispatch.

DeepSeekV4.1 Flash Free max returned a completed report while the outer adapter
reported adapter_timeout. It requested explicit read accounting/timing and a stop/
dispatch race definition. The contract now separates two tool-read attempts from
six model requests, bounds metadata checks, measures synchronous reader overruns
without claiming native-call preemption, and defines one owned advance step after
notification dispatch. Active validation/reservation/send entry share a synchronous
controller turn; only the coordinator owns the writer and admission stops use
its committed-core-stop/loop-fence route. An already-created request stays counted
as dispatched, with uncertainty retained if closure cannot be verified.

Flint40B Free's relay result failed without a report; its outer adapter also
reported adapter_timeout. No verdict is attributed to that run. `review.json`
records raw result/brief hashes and both status layers. None grants authorization.

Parent review checked actual Architecture4.2/5.1/5.3/11.2, existing MemberContext,
SDK session/member readers and the accepted scripted adapter. The tool explicitly
returns only the profile fields that exist; it invents no task/permission data.
The new loop-only profile preserves legacy tool refusal. Actual transmitted
structured result snapshots and real unchanged core projections are mandatory
test evidence, preventing a stub that bypasses the tool round trip from passing.
Core writing, live provider formats/network/credentials, MCP, durable loop replay
and UI remain outside the proposed scope. This task changes no accepted source
and executes no new loop or engine; the273-test baseline's seals are verified.
