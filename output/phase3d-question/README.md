# Phase 3D bound questions and actual-answer continuation

The owner-approved 11b19a7 contract connects the existing durable question engine
to a separate fixed offline loop profile. Role/recipient derive from the actual
bound core member. An accepted ask blocks the task and retains its slot while
the run waits with no adapter request, timer or scheduled pump.

The trusted coordinator records answers through existing core APIs. Explicit
resume with a unique ID reads only the author's bound question; open questions
stay waiting. Actual answers, routing and answerer enter a closed paired result
in a real continuation request. No prose, observer value or model input can
answer a question. Reports remain separately proof-gated.

Private IDs and attempts reserve before writes/reads. Thrown or measured-overrun
asks remain uncertain without retry, even with verified local cleanup. Known ask
state is distinct from the current durable question status. Stop/dispose fences
and drains waiting/resume resources before store/root cleanup. Old factories,
core/schema7 and mock-team production behavior remain unchanged.

TEST-PLAN.md defines the source preflight, finite actual-core matrix and budgets.
evidence.json/verification.json seal actual passing results; raw streams and any
failed attempts remain local under .git. Run
`rtk proxy python -X utf8 -B output/phase3d-question/verify.py` to check the seal.

This is implementation evidence; Phase3D exit is separately pending. Providers,
